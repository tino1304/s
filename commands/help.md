**S Plugin** — A Claude Code plugin for the lazy-prompt developer.

## Quick Start

1. **`/s:init`** — Run this first. Creates the `.claude/s/` folder structure.
2. **`/s:code [task]`** — Execute a task with matched skill guidelines loaded.
3. **`/s:launch [task]`** — Split a complex task into parallel sub-agents.

## All Commands

| Command | What it does |
|---------|-------------|
| `/s:code [task]` | Execute task with project skills |
| `/s:launch [task]` | Decompose into 2-5 parallel sub-agents |
| `/s:init` | Create `.claude/s/` folder structure |
| `/s:init-skill-mapper` | Regenerate `mapper.md` from existing skill files |
| `/s:scan` | Analyze codebase, generate structure docs |
| `/s:check-convention [path]` | Check code against skill conventions (path optional) |
| `/s:backlog` | Show pending TODOs |
| `/s:backlog-add [item]` | Add a TODO item |
| `/s:backlog-rm [#]` | Remove a TODO by number |
| `/s:help` | This guide |

## How It Works

```
/s:code build the auth handler
      │
      ▼
  Load .claude/s/skills/mapper.md → pick relevant skills from .claude/s/skills/ → execute with guidelines
      │
      ▼
  Hooks enforce rules throughout (write protection, research proof, no dev servers)
```

## Skills

Skills are project-specific guidelines generated by `/s:scan`. They live in `.claude/s/skills/` and are tailored to your project's actual tech stack, patterns, and conventions. Re-run `/s:scan` to regenerate.

## Tips

- Run `/s:init` once per project, then `/s:scan` to generate skills and docs.
- Use `/s:launch` for tasks that touch multiple areas (e.g. "build auth with API, UI, and tests").
- `/s:scan` generates docs in `.claude/s/docs/` with Mermaid diagrams.
