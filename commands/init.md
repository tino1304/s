---
description: Initialize S plugin for current project
---

1. Check `CLAUDE.md` exists. If missing → tell user to run `/init` first, STOP.

2. Read `CLAUDE.md` + project config files (`package.json`, `pubspec.yaml`, `go.mod`, `Cargo.toml`, `pyproject.toml`, `tsconfig.json`, `vite.config.*`, `next.config.*`, `tailwind.config.*`, `pom.xml`, `build.gradle`, `Gemfile`, `composer.json`, `mix.exs`, `Makefile`, `Dockerfile`, `docker-compose.*`) to detect tech stack.

3. **Ask user if they want to generate project skills.** Briefly describe: "I can analyze your codebase and generate skill guideline files tailored to your project's patterns and conventions. These will be saved to `.claude/s/skills/` and used by `/s:code` and `/s:launch` to follow your project's coding style." If `.claude/s/skills/` already exists, list existing skill files and ask if they want to **regenerate** or **keep current**.
   - If user **declines** → skip steps 4–7, go to step 8.
   - If user **confirms** → continue.

4. **Analyze project source code.** Browse key source files to understand:
   - Project structure (directory layout, naming conventions)
   - Architecture patterns (MVC, Clean Architecture, etc.)
   - Code style and common patterns (how handlers, components, data access, state, tests are written)
   - Existing conventions the project follows

5. **Determine skill topics** based on detected stack and code analysis. Common categories (generate only what applies, add custom topics if the project has unique concerns like auth, caching, i18n, realtime):
   - structure, components/widgets, state, data/database, api/handlers, testing, styling, errors, validation, concurrency

6. **Generate `.claude/s/skills/[topic].md`** for each topic:

```markdown
# [Topic Title]

[1-2 sentence summary in context of THIS project.]

## [Pattern Name]
```[language]
// Code example using THIS project's real types, file paths, function names.
```

## Rules
- [Prescriptive rule derived from this project's actual conventions]
```

**Generation rules:**
- Every code example MUST reflect THIS project's actual patterns, types, and conventions — not generic templates.
- Reference real files, real function names, real type names from the codebase.
- Be specific to the libraries this project uses (e.g. if Zustand, show Zustand — not Redux).
- Keep each file concise: 20-50 lines. Patterns to follow, not tutorials.
- Rules must be prescriptive ("Use X", "Never Y"), not descriptive.

7. **Create `.claude/s/skills/mapper.md`:**

```markdown
# Skill Map

## Stack
| Language | Framework | Styling | State | Build | Test | Other |
|----------|-----------|---------|-------|-------|------|-------|
| [detected] | [detected] | [detected] | [detected] | [detected] | [detected] | [detected] |

## Skills
| Skill | File | Keywords | Description |
|-------|------|----------|-------------|
| [name] | `[topic].md` | [keywords] | [one-line description] |

## Note for Agents
Read the skill file(s) relevant to your task from `.claude/s/skills/` before writing code. Skills contain project-specific patterns and rules — follow them.
Also read `.claude/s/mapper.json` for reusable code locations.
```

8. Scan project for reusable functions in common paths (utils, helpers, shared, lib, common, hooks, composables, pkg, internal/common, etc.) AND functions that are imported/used in many places across the codebase. Create `.claude/s/mapper.json` indexing each function with its name, file location, description, and keywords so agents can quickly find and reuse them. If none found, create template for user to configure:

```json
{
  "reusable": [
    { "name": "functionName", "path": "src/utils/file.ts:42", "description": "What it does", "keywords": ["keyword1", "keyword2"] }
  ]
}
```

9. Create `.claude/s/README.md`:

```markdown
# S Plugin Config

Auto-generated by `/s:init`. Edit these files to customize.

- **skills/** — Project-specific skill guidelines. Each `.md` file covers one development concern.
- **skills/mapper.md** — Index of all skills with keywords for matching.
- **mapper.json** — Reusable functions index.
- **backlog.md** — TODO items found in codebase.

Re-run `/s:init` to regenerate.
```

10. Scan all source files for TODO comments (`// TODO`, `# TODO`, `/* TODO`, `<!-- TODO`, `-- TODO`). Collect each with file path, line number, and the TODO text. Create `.claude/s/backlog.md`:

```markdown
# Backlog

TODOs found in codebase. Re-run `/s:init` to refresh.

| # | File | Line | TODO |
|---|------|------|------|
| 1 | `src/auth.ts` | 42 | TODO: add token refresh |
```

If no TODOs found, create the file with an empty table and a note: "No TODOs found."

11. Show summary: detected stack, number of skills generated (if any), list of created files, and path to skills folder. Do NOT modify CLAUDE.md.
